## 1. 하드웨어 구성

- 팔로워 1대 + 리더 1대 (각 12V, USB 시리얼). 모터 6개: shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll, gripper
- 카메라: 그리퍼 위 광각 USB 카메라 1대(키 `wrist`, 640×480 @ 30 fps). 전면 카메라는 사용하지 않음
- 처음에는 외장 카메라 2대(front / ego)로 시작했지만, 방과 사람을 비추고 작업대·그리퍼가 안 보였고, 두 카메라 사진이 똑같아 같은 장치를 두 번 연 것으로 의심됨 → 손목 카메라 1대로 정리
- 카메라를 USB 허브에 꽂으면 160×120으로 떨어지거나 멈춘 적이 있음 → PC에 직접 연결

## 2. 소프트웨어 패치 (`patches/lerobot_so_follower.patch`)

손목 회전(wrist_roll) 모터가 시작 직후 급회전하거나 반대로 돌고 `Overload error`가 나던 문제에 대한 완화 조치입니다.

1. 연결 시 현재 위치를 읽어 목표 위치로 설정 (남아 있던 목표값으로 튀지 않게)
2. wrist_roll의 목표와 현재 위치 차이가 45°를 넘으면 그 명령은 버리고 현재 위치 유지
3. 종료 시 모터 하나의 토크 해제가 실패해도 나머지는 계속 해제

근본 원인을 통제 실험으로 확정하지는 않았습니다. "모든 자세에서 안전"이 아니라 "정상 동작하던 구성의 완화 조치"입니다.

## 3. 안전 필터 (`autograsp/plugin/lerobot_robot_so101_safe`)

AI 정책이나 서보가 내는 모든 명령은 모터로 가기 전에 아래를 거칩니다.

- NaN/inf 등 이상한 값 → 그 자리에서 정지(hold)
- 관절 범위: 사람 시연에서 실제로 지나간 범위 + 5° (`derive_limits.py`로 생성)
- 한 번(틱)에 움직이는 각도 제한: 시연 속도 99퍼센타일 × 1.5, 최대 6°
- 카메라 프레임이 250 ms보다 오래되면 정지, 제어 루프가 150 ms를 5번 연속 넘으면 정지
- `Esc` 즉시 정지, `Space` 일시정지, 종료 시 천천히 쉬는 자세로 이동 후 확인을 받고 토크 해제

한계: 관절 공간 제한이라 테이블 높이 같은 직교 좌표 제한은 없습니다. 정지(hold)하면 그리퍼 힘도 약해져 들고 있던 물체가 떨어질 수 있습니다.

## 4. 방법 1 · AI 모방학습 실험 기록

### 모델 선택

| | ACT | SmolVLA |
|---|---|---|
| 입력 | 카메라 + 관절 | 카메라 + 관절 + **텍스트 명령** |
| 장점 | 학습이 빠름(4000 step 약 10~15분), 추론 약 12 ms | 사전학습 모델이라 환경 변화에 강할 가능성, "N번 칸으로" 같은 명령을 받을 수 있음 |
| 단점 | 명령을 못 받음(과제 하나만) | 약 4 GB 추가 설치, 학습이 느림 |

목표가 "N번 칸으로 옮겨"였기 때문에 SmolVLA를 주 모델로, ACT는 데이터 품질 확인용 기준으로 썼습니다.
LLM은 제어 루프에 넣지 않았습니다.

### 데이터셋

| 데이터셋 | 에피소드 / 프레임 | 비고 |
|---|---|---|
| `so101_smoke_2cam_320_001` | 1 / 50 (5 fps) | 관절이 전혀 안 움직인 정지 녹화 → 학습 불가 |
| `so101_sector_train_v1cam` | 27 / 11,730 (30 fps) | 테이프를 1~9번 칸으로 옮기기. 카메라 1차 장착(v1) |
| `so101_sector_train` | 9 / 4,336 (30 fps) | 주사위를 왼쪽 칸으로. 카메라 재장착(v2: 집게 두 개가 모두 보이게) |

### 학습과 실로봇 평가 결과

| 실험 | 데이터 / 학습량 | 실로봇 결과 | 주된 실패 |
|---|---|---|---|
| SmolVLA r1 (칸 1~9) | 26 에피소드(불량 1개 제외), 10,000 step | 0/7 (1회 집기는 성공했으나 놓기 실패) | 물체 쪽으로 제대로 다가가지 못함(F2) |
| SmolVLA left p1 (왼쪽 칸) | 9 에피소드, 3,000 step | 0/4 | 접근 실패(F2), 대상 선택 실패(F1) |
| ACT left p1 (왼쪽 칸) | 9 에피소드, 4,000 step | 0/2 | 대상 선택 실패(F1), 접근 실패(F2) |

알게 된 점

- 드라이런(녹화 데이터 재생 비교)에서는 오차가 1~3° 수준이라 괜찮아 보여도, 실제 로봇에서는 다른 결과가 나옴
- SmolVLA는 텍스트에 따라 다른 행동을 내는 것(언어 반영)은 확인됐지만, 정확히 집으려면 데이터가 훨씬 더 필요
- 실행 방식: 행동 청크를 기다렸다 실행하는 동기 방식보다 비동기 + 스무딩 실행기가 제어 주기를 29 Hz 가까이 유지(동기 약 25 Hz)
- 시연 중 노트북·손이 화면에 들어오거나 리더/팔로워 손목 각도가 어긋나면 데이터 품질이 떨어짐 → 녹화 전 정렬(`align_check.py`) 필요
- 결론: 마감 안에 수업에서 안정적으로 보여 주기에는 학습 없는 방법이 필요 → 방법 2

## 5. 방법 2 · 색 검출 + 비주얼 서보

학습 없이 손목 카메라 화면만으로 집는 방법입니다.

1. **주사위 찾기** (`dice_detect.py`): HSV 색 범위로 주사위 색을 골라내고, 거의 정사각형으로 꽉 찬 덩어리만 주사위로 인정. 이전 위치에서 너무 멀리 튄 덩어리(잔디, 트랙 무늬 등)는 무시
2. **자코비안 측정**: 관절을 4°씩 살짝 움직여 보고 화면 속 주사위의 (x, y, 크기)가 어떻게 바뀌는지 측정
3. **다가가기**: 목표(집게가 주사위를 감싼 상태에서의 화면 위치·크기)와의 차이를 줄이는 방향으로 매 틱 관절을 조금씩 움직임 (감쇠 최소제곱, Broyden 갱신으로 자코비안 보정)
4. 수렴하면 집기 → 들어 올려 놓을 자세로 이동 → 놓기

### 최종 결과: 주사위 집어 옮기기 성공 (2026-10-24)

야외 행사장 테이블(3×3 칸 판)에서 초록색 큰 주사위를 손목 카메라만으로 찾아가 **집은 뒤, 들어 올려 왼쪽 칸에 놓기까지 성공**했습니다.
AI 모방학습(방법 1)이 한 번도 성공하지 못한 것과 달리, 학습 데이터 없이 처음으로 과제 전체(찾기 → 다가가기 → 집기 → 옮기기 → 놓기)를 자율로 해낸 결과입니다.

| 항목 | 값 |
|---|---|
| 방법 | 색 검출 + 비주얼 서보 (`servo_pick.py`), 학습 없음 |
| 카메라 | 손목 카메라 1대 (640×480) |
| 물체 | 초록 주사위 (`rig.json` `"dice_color": "green"`) |
| 집기 목표 | `--teach-grasp`로 직접 가르친 화면 위치 (cx 300, cy 144, 면적 13,526 px) |
| 놓기 | `--teach-place`로 가르친 놓을 자세로 이동 후 그리퍼 열기 → 왼쪽 칸 안에 놓임 |
| 확인 자료 | `autograsp/runs/servo/grasp_before.jpg`(수렴 직후), `grasp_after.jpg`(집은 뒤) — 두 사진 모두 주사위가 두 집게 사이에 들어와 있음. 놓기 성공은 현장에서 직접 확인 |

성공에 결정적이었던 변경

- **빨강 → 초록 주사위**: 장면 위쪽의 빨간/검은 표식과 헷갈리던 문제가 사라짐
- **모양 필터**: 거의 정사각형으로 꽉 찬 덩어리만 주사위로 인정 (잔디, 트랙, 테이프를 무시)
- **집기 목표를 직접 가르치기**: 예전 시연에서 계산한 목표 대신, 집게를 주사위에 실제로 대 보고 그때의 화면 위치·크기를 목표로 사용
- **서보 중 재탐색 금지 + 튐 제한(80 px)**: 한 프레임 놓쳤을 때 엉뚱한 곳으로 뛰어가지 않음
- **크기 오차 가중치**: 가운데 맞추기와 다가가기가 서로 상쇄되어 멈추던 문제 완화

## 6. 수업 이후 추가된 기능

| 기능 | 사용법 | 내용 |
|---|---|---|
| 주사위 색 선택 | `rig.json`에 `"dice_color": "green"` | 빨강/초록 지원. 빨간 표식과 헷갈리지 않게 초록 주사위 사용 가능 |
| 집기 목표 직접 가르치기 | `servo_pick.py --teach-grasp` | 토크를 풀고 집게를 주사위 둘레에 손으로 둔 뒤 `s` → 그때의 화면 위치·크기를 서보 목표로 저장 |
| 반복 실행 | `servo_pick.py --loop` | 시작 자세에서 주사위가 보이면 집어 옮기기를 반복. 연속 5번 실패하면 중단(`--max-fails`) |
| 튐 방지 | `--max-jump 80` | 서보 중 주사위를 놓치면 다른 곳으로 다시 찾지 않고 멈춤(20틱 연속 놓치면 중단) |
| 다가가기 가중치 | `--size-weight` | 가운데 맞추기 때문에 "가까이 가기"가 희생되지 않도록 크기 오차에 가중치 |
| 확인용 사진 | 자동 | `autograsp/runs/servo/`에 `grasp_before.jpg`, `servo_lost.jpg` 등 저장 |

## 7. 자주 겪은 문제

| 문제 | 원인 / 해결 |
|---|---|
| 녹화 명령에 이상한 인자가 들어감 | PowerShell 인자 전달 문제 → JSON 설정 파일로 녹화 |
| `checkpoints/last` 만들 때 WinError 1314 | Windows symlink 권한 → `train_shim.py`가 junction으로 대체 |
| torchcodec 로드 실패 | 시스템 FFmpeg 없음 → `video_backend=pyav` |
| 카메라 2대 640×480 동시 사용 시 지연 | USB 대역폭으로 추정(미확정) → 카메라 1대로 정리 |
| 모터 6개 동시 무응답 (`There is no status packet`) | 12V 전원·케이블 확인 |

## 8. 남은 과제

- 방법 1: 칸마다 충분한 시연(칸당 5회 이상, 총 50개 이상)을 다시 모으고, 학습에 쓰지 않은 조건으로 따로 평가
- 방법 2: 여러 번 반복해 성공률 기록(`--loop`), 1~9번 칸 지정 놓기(텍스트 명령 → 놓을 자세 선택), 조명 변화에 강한 색 검출
- 직교 좌표 기반 안전 제한(테이블 아래로 내려가지 않게)
